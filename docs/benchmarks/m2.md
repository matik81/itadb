# Benchmark M2 — aggregati inventati

Estratto storico con sistema operativo originario omesso. Misure invariate;
non è un benchmark della baseline Linux corrente. Rapporto originale conservato
nell’archivio locale.

Eseguito il 23 settembre 2026 con `scripts/benchmark_m2.py`, database isolato
vuoto, PostgreSQL 17.5/PostGIS 3.5 in Docker, host della misura storica con AMD Ryzen
9 9900X (12 core/24 thread). `shared_buffers=128MB`, `work_mem=4MB`.

Il generatore produce 8.000 territori inventati × 128 serie, tutte valore 1,
per un solo periodo e release. Ogni batch inserisce 64.000 osservazioni;
trigger e indici rimangono attivi. Geometrie e artefatti sono fixture esplicite.
Questa prova misura il motore SQL, non l'acquisizione, la normalizzazione Python
o la correttezza di una sintesi demografica. La pipeline reale è stata verificata
separatamente sulle 22.678 osservazioni ufficiali e 24.091 territori versionati.

| Misura | Risultato |
|---|---:|
| Osservazioni caricate | 1.024.000 |
| Preparazione dimensioni e caricamento | 29,86 s |
| Incremento dimensione DB, inclusi indici e fixture | 178.541.948 byte |
| Differenza contatore WAL del server | 555.546.288 byte |
| Query paginate, 100 righe, cursori e serie variabili | 100 |
| Latenza client SQL p50 | 1,79 ms |
| Latenza client SQL p95 | 2,36 ms |
| EXPLAIN finale: pianificazione / esecuzione | 0,340 / 0,605 ms |

Il piano usa `observation_p5_pkey` e una sola delle otto partizioni;
`territory_pkey` risolve le dimensioni. Nessun file temporaneo nel piano finale,
609 blocchi condivisi trovati in cache. La scansione sequenziale riguarda la
piccola dimensione delle serie, non il milione di osservazioni.

Limiti: cache non svuotata, client SQL locale, nessun carico HTTP concorrente
controllato. Durante la misura giravano anche test isolati sul medesimo server:
latenze e soprattutto il contatore WAL globale possono includerne il costo.
Picco RSS non misurato: i valori di configurazione non sono consumo RAM.
Non estrapolare a 60 milioni di agenti, valori ad alta entropia, tutte le serie
territoriali o carichi produttivi. Non è un SLA.

Rapporto completo locale, con tempi di tutte le query e piano JSON:
`data/reports/m2-benchmark-7102b1ae-b0e6-411b-84a2-85b015de7d64.json`.
Il comando richiede `ITADB_TEST_DATABASE_URL` e rifiuta cataloghi non vuoti;
avviarlo con `scripts/run_logged.py` per progresso, conteggi e durata.
